# Publication profiles

The project has one calibrated scientific core and two reporting profiles. This
keeps every parameter draw and clinical assumption identical while changing
the comparator used for each scientific reporting profile.

| Item | EJPC profile | DOM profile |
|---|---|---|
| Runner | `source("run_ejpc.R")` | `source("run_dom.R")` |
| Recommended one-run option | `source("run_all.R")` | already generated by the same run |
| Benchmark | SELECT-like trial implementation | full treatment persistence |
| Primary retained-benefit denominator | no treatment minus SELECT-like MACE | no treatment minus full-persistence MACE |
| Output tables | `results/ejpc/` | `results/dom/` |
| Output figures | `figures/ejpc/` | `figures/dom/` |
| Interpretation | implementation gap between trial and routine care | treatment persistence and cardiometabolic rebound |
| Working title | *How Much SELECT Benefit Survives Real-World Semaglutide Discontinuation? A Dynamic Cardiovascular Outcomes Model* | *Projected Cardiovascular Benefit of Semaglutide Under Real-World Discontinuation, Reinitiation, and Weight Regain: A Dynamic Model* |

## Why the model is not duplicated

Duplicating the model would allow bug fixes, calibration, or random draws to
drift between submissions. `run_all.R` instead runs the model once, stores the
shared calibration and probabilistic draws in `results/shared/`, and then
creates both journal-specific denominators, tables, and figures.

## Interpreting the profiles

Both estimates are reported transparently and should not be compared as if
 they were generated from independent models. The profile switch changes
 the denominator, not the calibrated parameter set or simulation design.
